1. Direktlink empfohlen

    
Jedes Spiel liegt in einem eigenen Ordner und ist eine vollständige Seite:


<a href="zotik/">ZOTIK spielen</a>

    
    
      
  • Das Spiel öffnet als ganze Seite. Vollbild, Zurück-Taste und Tastatur regelt der Browser bzw. das Spiel.
    • 
      
  • Mit target="_blank" öffnet es in einem neuen Tab.
    • 
      
  • Die Ordnernamen (Spiel-IDs) stehen in games.js und im Generator oben.
    • 
      
  • Direkt in die Übersicht springen und das Spiel dort öffnen: #zotik (der Viewer öffnet es vollflächig; echtes Vollbild braucht zusätzlich einen Tipp).
    • 
    

  


  

    
2. Ein Spiel als iframe


<iframe src="zotik/" title="ZOTIK"
  allow="fullscreen; autoplay; gamepad; accelerometer; gyroscope" allowfullscreen loading="lazy"
  style="width:100%;max-width:960px;aspect-ratio:16/10;border:0;border-radius:12px"></iframe>

    
Wichtig: Ohne allow="fullscreen" kann im iframe kein Vollbild gestartet werden. Ohne autoplay bleibt Ton oft stumm, bis jemand tippt.

    
    
      
  • Hochformat-Spiele: aspect-ratio:9/16 oder eine feste Höhe nehmen.
    • 
      
  • Das Spiel hat im iframe kein Menü zum Schließen. Das liefert deine Seite.
    • 
      
  • Einfacher mit Vollbild-Knopf: easygames.js.
    • 
    

  


  

    
3. easygames.js – per Attribut oder JavaScript

    
Einmal einbinden. Das Script lädt die Spieleliste selbst und findet seinen Pfad automatisch.


<script src="easygames.js"></script>

    
Variante A – nur HTML


<div data-easygames="zotik"></div>
<div data-easygames="anmacha-snake" data-ratio="4/3" data-max-width="720px"></div>
<div data-easygames="all"></div>   <!-- komplette Bibliothek -->

    
Variante B – JavaScript mit Variablen


<div id="ziel"></div>
<script>
  const spielId = 'zotik';   // beliebige Spiel-ID, z. B. aus einer Datenbank oder URL
  EasyGames.embed('#ziel', { game: spielId, ratio: '16/10', maxWidth: '960px' });
  // Bibliothek: EasyGames.library('#alle');
</script>

    
Android (ES-DE für Android)

    
Unter Android gibt es kein Skript und kein Python. Dort startet EmulationStation installierte Apps. Zwei Wege (nach meinem Kenntnisstand, auf Android noch nicht getestet):

    
    
      
  • easygames-App: Die Android-App (APK, siehe Download-Karte oben) enthält alle Spiele und läuft offline. ES-DE für Android zeigt installierte Apps im System „Android“ an; dort die easygames-App starten oder als Favorit markieren.
    • 
      
  • Einzelne Spiele als Apps: Jedes Spiel lässt sich über seinen Direktlink in Chrome als App installieren (Menü → „App installieren“). Installierte Spiele erscheinen wie andere Apps in der Android-Liste.
    • 
      
  • Ein einzelnes Spiel direkt aus der EmulationStation-Spieleliste zu starten, geht auf Android noch nicht (die App hat keine Direktlinks auf einzelne Spiele).
    •

Funktionen

    

      
AufrufErgebnis

      
EasyGames.embed(ziel, optionen)Setzt ein Spiel in das Ziel (Selektor oder Element).

      
EasyGames.library(ziel, optionen)Setzt die komplette Übersicht ein.

      
EasyGames.ready(callback)Ruft zurück, sobald die Spieleliste geladen ist.

      
EasyGames.list()Alle Spiele: id, title, desc, icon, url, card, bg, glow (bg/glow = Spielfarben für eigene App-Kacheln). Praktisch für eigene Menüs.

      
EasyGames.get(id) / url(id)Ein Spiel bzw. nur seine URL.

      
EasyGames.guide(id, cb)Anleitung und Bedienung als Objekt {anleitung, steuerung, tipps}.

      
EasyGames.open(id | 'all', optionen)Öffnet ein Spiel oder den ganzen Katalog vollflächig als Overlay (close, fullscreen, title, onClose).

      
EasyGames.close()Schließt das offene Overlay.

      
EasyGames.fullscreen(iframe)Startet Vollbild; fällt auf einen neuen Tab zurück, wenn der Browser es nicht kann (z. B. iPhone).

      
EasyGames.tvUrl(id)Link für den TV (öffentliche Adresse, ggf. mit ?tv); null bei Einzelspielen, siehe TV-Link.

      
EasyGames.device()Geräteinfos (Typ, Rolle, Eingaben …), siehe Geräteerkennung.

      
EasyGames.scan()Sucht neu hinzugefügte data-easygames-Elemente (für dynamische Seiten).

    

    
Eigenes Spielmenü bauen


<script>
  EasyGames.ready(() => {
    EasyGames.list().forEach(g => {
      const a = document.createElement('a');
      a.href = g.url; a.textContent = g.title;   // Direktlink im Vollbild
      document.body.appendChild(a);
    });
  });
</script>

  


  

    
4. Ganze Bibliothek einbetten


<iframe src="?embed=1" title="easygames"
  allow="fullscreen; autoplay; gamepad; accelerometer; gyroscope" allowfullscreen
  style="width:100%;height:90vh;border:0"></iframe>

    
    
      
  • Die Übersicht mit Suche und Anleitungen erscheint, ohne Kopfzeile (?embed=1).
    • 
      
  • Ein Tipp auf ein Spiel öffnet es im Vollbild-Viewer, der den iframe ausfüllt und Vollbild anfordert. Dafür ist allow="fullscreen" nötig.
    • 
      
  • Gib dem iframe genug Höhe (z. B. 90vh), sonst wird der Viewer klein.
    • 
      
  • Ein bestimmtes Spiel gleich öffnen: ?embed=1#zotik.
    • 
    

    
URL-Parameter der Übersicht

    

      
ParameterWirkung

      
?embed=1Einbettungsmodus: keine Kopfzeile, kein Footer.

      
?tv=1 / ?tv=0TV-Modus erzwingen oder abschalten (sonst automatisch bei Smart-TV-Browsern).

      
?device=tv|phone|tablet|desktopGerätetyp vorgeben, z. B. zum Testen.

      
#spiel-idÖffnet das Spiel direkt im Viewer.

    

  


  

    
5. Vollbild

    
    
      
  • Übersicht: Der Viewer ist immer vollflächig und fordert beim Öffnen Vollbild an. Die Menüleiste blendet sich nach ein paar Sekunden aus. Ein kleiner Tab oben holt sie zurück.
    • 
      
  • iframes auf fremden Seiten: Brauchen allow="fullscreen". Fehlt es, bleibt das Spiel in der iframe-Größe.
    • 
      
  • Nutzer-Geste: Browser erlauben Vollbild nur nach einem Tipp oder Klick. Die Übersicht fordert es deshalb beim Tippen auf ein Spiel an.
    • 
      
  • iPhone/iPad Safari: Kein Vollbild für Elemente. EasyGames.fullscreen() öffnet dann das Spiel als eigene Seite in einem neuen Tab. Für Handys ist ein Direktlink deshalb oft die beste Wahl.
    • 
      
  • Direkt im Vollbild einbinden: siehe unten – ganze Seite oder Overlay, für ein Spiel oder den ganzen Katalog.
    • 
      
  • Hoch-/Querformat: Die Übersicht erzwingt keine Ausrichtung; ob ein Spiel Quer- oder Hochformat bevorzugt, entscheidet das Spiel.
    • 
    

  


  

    
5a. Spiel oder Katalog direkt im Vollbild

    
Zwei Darstellungen füllen das ganze Fenster – für ein einzelnes Spiel und für den ganzen Katalog (all). Beide stellt der Code-Generator unter „Darstellung“ ein.

    

      
DarstellungHTMLWirkung

      
Ganze Seite<div data-easygames="zotik" data-mode="page"></div>Das Spiel (oder mit all der Katalog) füllt dauerhaft das ganze Fenster. Gedacht für eine eigene Spiele-Seite.

      
Overlay<button data-easygames="zotik" data-mode="overlay">Spielen</button>Ein Klick öffnet das Spiel (oder den Katalog) vollflächig über deiner Seite und fordert das Browser-Vollbild an.

    


<script src="easygames.js"></script>

<!-- ganzer Katalog, ganze Seite -->
<div data-easygames="all" data-mode="page"></div>

<!-- ein Spiel per Knopf im Vollbild; mit JavaScript: -->
<button data-easygames="anmacha-quiz" data-mode="overlay">Quiz spielen</button>
<button onclick="EasyGames.open('all')">Alle Spiele</button>

<!-- App-Kacheln: Katalog als Symbolraster, oder ein einzelnes Spiel als Kachel -->
<div data-easygames="all" data-layout="apps"></div>
<div data-easygames="zotik" data-layout="tile" data-mode="overlay"></div>

    
Das Overlay

    
    
      
  • Schließen mit dem ✕-Knopf (mit data-close="false" bzw. { close:false } ausblenden), der Zurück-Taste des Browsers/Handys, Esc (wenn der Fokus nicht im Spiel liegt) oder per EasyGames.close(). Ein Spiel kann sich auch selbst schließen (easygames:close).
    • 
      
  • Die Seite dahinter scrollt nicht. Das Browser-Vollbild wird beim Klick angefordert; wo es der Browser nicht erlaubt (z. B. iPhone), bleibt das Overlay trotzdem vollflächig.
    • 
      
  • Barrierefreiheit: Das Overlay ist ein role="dialog" mit aria-modal; die Seite dahinter wird für Screenreader und Tastatur gesperrt (aria-hidden/inert), der Fokus liegt im Spiel, der Tabulator bleibt im Overlay und beim Schließen kehrt der Fokus zum auslösenden Knopf zurück. Dazu schließen auch die Zurück-Tasten von TV und WebView.
    • 
      
  • Nur ein Overlay gleichzeitig; ein neues ersetzt das offene. EasyGames.open('zotik', { fullscreen:false, title:'…', onClose: fn }) bietet weitere Optionen.
    • 
      
  • Controller und Sensoren: Alle eingebetteten Fenster erlauben jetzt gamepad, accelerometer und gyroscope; ohne diese Freigabe funktionieren Gamepad und Neigungssteuerung in fremden Seiten nicht. Bei eigenem iframe bitte allow="fullscreen; autoplay; gamepad; accelerometer; gyroscope" setzen.
    •

In den Spielen selbst gibt es dafür keine Oberfläche: nichts verdeckt Spielinhalt, die Spiele melden Bestwerte und Spielspuren nur still im Hintergrund.

So funktioniert es auf deiner Seite oder in deiner App

    
    
      
  • Keine eigene Firebase-Einrichtung nötig: Die Seiten laufen im Rahmen von easygames (eigene Adresse, bereits freigegeben). Die Google-Anmeldung passiert dort im Rahmen; deine Seite muss keine Domain freischalten.
    • 
      
  • Anpassungen: ?embed=1 blendet den Knopf „← Spiele“ aus (macht easygames.js automatisch). Größe, Seitenverhältnis und Rahmen steuerst du wie bei Spielen (data-ratio, data-max-width, data-mode).
    • 
      
  • 🐞 Fehler melden: bug.html (Generator oben: „Fehler melden“, data-easygames="bug", EasyGames.open('bug', { game: 'snake' }), EasyGames.bug('#ziel')). Angemeldete Spieler schicken Spiel, Art und Beschreibung (optional mit technischen Angaben) direkt an dich; ohne Anmeldung gibt es den Ausweg über GitHub. Auf deiner Seite genügt ein Knopf – das Spiel kann über data-game vorgewählt werden (hier die Cloud-ID, z. B. snake).
    • 
      
  • 💬 Chat: chat.html (Generator oben: „Chat“, data-easygames="chat" data-room="lobby", EasyGames.open('chat', { room: 'tipps' }), EasyGames.chat('#ziel', { room })). Räume: lobby, mitspieler, tipps, g-<spiel-id> (z. B. g-snake für einen Spiel-Chat). Nur für angemeldete Spieler, mit Wortfilter, Melden und Ausblenden; auf einer anderen Adresse meldet sich der Spieler im Chat einmal an.
    • 
      
  • 👤 Konto (einmal anmelden, überall angemeldet): konto.html (Generator oben: „Konto“, data-easygames="konto", EasyGames.open('konto'), EasyGames.account('#ziel')). Die Seite zeigt die Google-Anmeldung, Name, Rang, Erfolge und die gesicherten Spielstände. Alle Spiele unter derselben Adresse übernehmen die Anmeldung automatisch; im Cloud-Fenster jedes Spiels führt „👤 Konto“ dorthin. Auf einer anderen Adresse (eigene Seite, anderer Browser) gilt die Anmeldung nur dort – dort einmal anmelden (oder die Konto-Seite einbetten); Spielstände, Erfolge und Ranglisten-Profil kommen danach automatisch aus dem Google-Profil.
    • 
      
  • Erfolge sind pro Gerät und Adresse: Sie werden aus den Spielständen berechnet, die unter derselben Adresse gespeichert sind. Wer easygames im Browser (github.io) spielt, sieht sie dort; mit Google-Anmeldung folgen sie dem Spieler auf alle Geräte und Apps.
    • 
      
  • In Apps (Android/Windows): Die Seiten sind Teil des Offline-Standes (ranglisten.html, erfolge.html, konto.html, chat.html, bug.html, cloud/anmacha-bug.js, cloud/anmacha-chat.js, cloud/anmacha-chatfilter.js, cloud/anmacha-board.js, cloud/anmacha-ach.js, cloud/anmacha-gameach.js, sync/catalog.json). Die Anmeldung geschieht über die Kopplung: ☁ in einem Spiel ▸ Link im Browser öffnen ▸ danach erscheint das Konto auch in Ranglisten und Erfolgen.
    • 
      
  • Eigene Seite mit eigenen Spielen: Die Spielliste kommt aus sync/catalog.json (node tools/build-sync.js). Neue Spiele bekommen Ranglisten und Erfolge automatisch, sobald sie cloud/anmacha-cloud.js einbinden (Cloud-Speicherstand); besondere Wertungen trägst du in cloud/anmacha-board.js (REG) ein, ein leerer Eintrag schaltet die Rangliste eines Spiels ab.
    • 
      
  • Grenzen: Die Werte stammen vom Gerät des Spielers und sind nicht manipulationssicher (Spaß-Ranglisten). Die Erkennung der Bestwerte ist eine Heuristik über typische Feldnamen (best, highscore, wins, stars …).
    • 
      
  • Einmalig in der Firebase-Konsole (nur der Betreiber von easygames, nicht deine Seite): die Regeln aus cloud/firestore.rules veröffentlichen, sonst zeigen die Ranglisten „noch nicht freigeschaltet“. Die Erfolge brauchen keine neue Regel.
    •

easygames erkennt selbst, auf welchem Gerät es läuft. Die Übersicht passt sich an (TV-Layout, Hinweise, Filter), und Spiele können dasselbe nutzen.

So funktioniert die Handy-Kopplung bei den Spielen

    
    
      
  • Spiele mit 📱 Handy-Controller (Kart Rush, Quiz, Koffer Dealer, Hörerwahl, Frequenzrad, Preisradar, Funkparcours, Funkhaus Reality, Mach mich aus!) laufen am PC oder TV als Gastgeber und zeigen einen QR-Code.
    • 
      
  • Das Handy öffnet über den QR-Code dieselbe Spielseite mit ?join=CODE und wird automatisch zum Controller. Dafür braucht es keine Auswahl in der Übersicht.
    • 
      
  • Am TV öffnet die Übersicht Kart Rush mit ?tv, dann erscheint direkt die Lobby mit QR-Code.
    • 
      
  • Den QR-Code erzeugt das Spiel aus seiner eigenen Adresse. Spiele im Viewer der Übersicht liefern deshalb den direkten Spiel-Link, den Handys ohne Übersicht öffnen.
    • 
    

    
Für Spiele-Entwickler: Gerät im Spiel nutzen


// A) device.js im Spiel einbinden
<script src="../device.js"></script>
if (EasyGamesDevice.joinCode()) startAsController();
else if (EasyGamesDevice.is('tv')) startAsHostWithQr();

// B) Läuft das Spiel im Viewer der Übersicht, kommt das Gerät auch per Nachricht
addEventListener('message', e => {
  if (e.data && e.data.type === 'easygames:device') use(e.data.device);
});
parent.postMessage({ type: 'easygames:getDevice' }, '*');   // jetzt anfordern
// Bei gleicher Herkunft steht es auch als window.EASYGAMES_DEVICE bereit.

Als App installieren (PWA)

    
Jedes Spiel lässt sich über seinen Direktlink auf dem Handy als App installieren – ohne Store, im Vollbild, mit Symbol auf dem Startbildschirm.

    
    
      
  • Android/Chrome: Hinweis „📲 Als App installieren“ oder Menü ▸ „App installieren“. iPhone: Teilen ▸ „Zum Home-Bildschirm“.
    • 
      
  • Nach dem ersten Spielen läuft die App offline und aktualisiert sich automatisch (Service Worker: Netz zuerst, bei schlechtem Netz aus dem Zwischenspeicher).
    • 
      
  • Der Installationshinweis erscheint nicht, wenn das Spiel in einem iframe eingebettet ist, in den RicoReWi-Apps und im bereits installierten Fenster.
    •

Alle Spiele lassen sich mit einem Gamecontroller (Xbox, PlayStation, 8BitDo …, per USB oder Bluetooth) spielen. Spiele mit eigener Controller-Steuerung brauchen nichts; alle anderen binden gamepad.js ein:


<script src="../gamepad.js" defer></script>
<script src="../gamepad.js" data-pad="a=Space/Enter ls=wasd y=-" defer></script>   <!-- eigene Belegung -->

    
    
      
  • Steuerkreuz und linker Stick = Pfeiltasten (ls=wasd: W A S D), A = Enter, B = Esc, X = Leertaste, Y = E, LB/RB = Q/E, Start = P, Select = M. Jede Taste ist per data-pad änderbar, - bedeutet „nichts“, a=Space/Enter sendet erst die Leertaste und nur wenn das Spiel sie nicht verarbeitet zusätzlich Enter.
    • 
      
  • In Menüs ohne Pfeiltasten-Steuerung springt das Steuerkreuz von Knopf zu Knopf (gelber Rahmen), A drückt ihn. Der rechte Stick bewegt einen Mauszeiger, A klickt (halten = ziehen).
    • 
      
  • Spiele mit eigener Controller-Steuerung binden die Datei nicht ein, damit nichts doppelt reagiert. Texteingaben gehen weiterhin über Tastatur oder Handy-Pads.
    • 
    

  


  

    
Cloud-Speicherstand (Google)

    
Spieler können ihren Fortschritt mit einem Klick auf ☁ ▸ „Mit Google anmelden“ sichern; er folgt ihnen dann auf jedes Gerät. Ohne Anmeldung bleibt alles im Browser des Geräts (localStorage) und das Spiel läuft unverändert.

    
Ein Spiel anbinden (eine Zeile vor </body>):


<script src="../cloud/anmacha-cloud.js" data-game="snake" data-prefix="anmachaSnake" defer></script>

    
    
      
  • data-prefix: Anfänge der localStorage-Schlüssel, die mitgesichert werden (kommagetrennt). Am Spielcode ändert sich nichts.
    • 
      
  • Pro Schlüssel gewinnt der neuere Zeitstempel. Geschrieben wird gebündelt (3 s nach einer Änderung und beim Verlassen), geladen beim Start.
    • 
      
  • In den Apps (Android/Windows) gilt eine Kopplung: Google sperrt die Anmeldung in App-Fenstern, deshalb zeigt die App einen Link, man meldet sich damit im Browser auf ricorewi-radio.de an, und die App übernimmt den Cloud-Speicher automatisch.
    • 
      
  • Ranglisten und Erfolge kommen mit demselben Skript automatisch dazu (ohne Oberfläche im Spiel): Bestwerte werden – nur mit Freigabe des Spielers – still eingereicht, Spielspuren für die Erfolge lokal mitgeschrieben. Anzeigen und einbinden: 5b. data-board="off" schaltet das für ein Spiel ab.
    • 
      
  • Die einmalige Einrichtung (Firebase-Projekt, Regeln, freigegebene Domains) steht in cloud/README.md.

Android-App mit Offline-Sync

    
⬇ Android-APK herunterladen

    
Die App ist eine native Android-Hülle (Kotlin) um die easygames-Oberfläche. Sie speichert alle Spiele samt Bibliotheken auf dem Gerät und hält sie über GitHub aktuell – ohne neues APK.

    
So kommen Updates auf das Handy

    
    
      
  1. Push auf GitHub: Ein Spiel wird geändert oder ein neues kommt dazu.
    2. 
      
  2. Manifest: Der Server-Job (android/server/, systemd-Timer, alle 10 Minuten) holt den neuesten Stand, berechnet sync/manifest.json neu (Liste aller Dateien mit Prüfsumme, dazu sync/catalog.json mit Spielen, Handbuch, Größen) und pusht es nach GitHub, falls sich etwas geändert hat. GitHub Actions werden nicht gebraucht.
    3. 
      
  3. Sync in der App: Sobald WLAN verbunden ist (und beim Start), lädt die App das Manifest, vergleicht Prüfsummen und lädt nur geänderte Dateien. Jede Datei wird geprüft, erst wenn alles da ist, wird der neue Stand aktiv. Ein Abbruch lässt den alten Stand unberührt.
    4. 
      
  4. Aktivieren: Mitten im Spiel passiert nichts. Danach zeigt die App „Update bereit – Neu laden“, spätestens beim nächsten Start ist alles aktuell.
    5. 
    

    
Offline

    
    
      
  • Das APK enthält einen Start-Stand aller Spiele, die App läuft also sofort ohne Internet.
    • 
      
  • Benachrichtigungen: Die Android-WebView kennt die Browser-Funktion Notification nicht; die App stellt sie den Spielen bereit (Notification.permission, requestPermission(), new Notification(titel, { body, tag })). Ab Android 13 erscheint der System-Dialog „Benachrichtigungen erlauben“, Tippen auf die Meldung öffnet die App. Es sind lokale Meldungen des laufenden Spiels (kein Server-Push, keine Zustellung bei pausierter App).
    • 
      
  • Bibliotheken, die Spiele von CDNs laden (three.js, PeerJS, QR-Code, Schrift Fredoka), liegen in vendor/. Die App fängt die Anfragen ab und liefert die lokale Datei – die Spiele selbst bleiben unverändert. Die Zuordnung steht in vendor/map.json.
    • 
      
  • node tools/offline-audit.js prüft, dass jedes Spiel nur mit dem Offline-Paket lädt. node tools/build-sync.js --strict meldet neue, noch nicht lokal vorhandene CDN-Bibliotheken.
    • 
      
  • Braucht weiter Internet: Online-Mehrspieler (PeerJS-Kopplung), Radio-Streams, Cloud-Speicherstand und Links wie das RicoReWi Radio.
    • 
    

    
Bauen

    
Die App wird auf eurem Server gebaut (android/build.sh, Anleitung in android/README.md). Ein neues APK ist nur für App-Änderungen nötig, nicht für Spiele-Updates.

  


  

    
EmulationStation & Retro-Konsolen neu

    
Alle easygames-Spiele lassen sich mit einem Skript in EmulationStation einrichten (ES-DE, RetroPie, Batocera/Ports und ähnliche Frontends). ⬇ emulationstation.py herunterladen

    
Was du brauchst

    • 
      
  • Einen Browser: Chromium, Chrome, Edge oder Firefox. Er wird automatisch gefunden (sonst --browser PFAD).
    • 
      
  • Ein installiertes Frontend (ES-DE, RetroPie, Batocera …).
    • 
    

    
Schnellstart (online)

    
Das Startprogramm prüft, ob Python da ist, und bietet bei Bedarf mit Rückfrage die Installation an (nichts passiert ohne dein Ja). Danach richtet es alle Spiele ein.

    
Windows (PowerShell; Python wird bei Bedarf über winget installiert):


Invoke-WebRequest https://ricorewioriginal-collab.github.io/easygames/tools/install-emulationstation.ps1 -OutFile install-emulationstation.ps1
powershell -ExecutionPolicy Bypass -File .\install-emulationstation.ps1

    
Linux, Steam Deck, RetroPie, macOS (Terminal; Python wird bei Bedarf über den Paketmanager installiert):


curl -fsSLO https://ricorewioriginal-collab.github.io/easygames/tools/install-emulationstation.sh

Danach EmulationStation neu starten. Das Skript erkennt das Frontend selbst. Alle Optionen (siehe unten) hängst du einfach an, zum Beispiel sh install-emulationstation.sh --mode offline. Mit --frontend es-de|retropie|ports und --roms ORDNER lässt sich das Frontend festlegen. Neue Spiele holst du, indem du das Startprogramm einfach erneut ausführst.

    
Hast du Python schon, geht es auch direkt: emulationstation.py laden und python3 emulationstation.py install ausführen.

    
Offline-Variante


git clone --depth 1 https://github.com/ricorewioriginal-collab/easygames
python3 easygames/tools/emulationstation.py install --mode offline

    
Dabei startet beim Spielstart ein kleiner lokaler Webserver (nur dein Gerät), der die Dateien aus dem Ordner liefert. Einige Spiele laden ihre 3D-Bibliothek (three.js) oder Schrift beim ersten Start noch aus dem Internet. Die komplett offline lauffähige Fassung aller Bibliotheken steckt in den Apps. Für den Dauerbetrieb ganz ohne Netz ist daher die Android-App der sicherere Weg; die Offline-Variante ist für das Wohnzimmer mit schwachem Netz gedacht.

    
Optionen

    

      
OptionWirkung

      
--mode online|offlineVon der Homepage (Standard) oder aus lokaler Kopie spielen.

  • Handy als Controller: Viele Mehrspieler-Spiele (Quiz, Rennen, Show-Spiele) koppeln Handys per QR-Code. Mit --tv erscheint der Code gleich beim Start – ideal am Fernseher.

  • Die Skripte liegen unter …/ROMs/easygames/. Ein Spiel lässt sich einzeln testen: python3 …/.easygames/emulationstation.py launch anmacha-quiz --window.

Link für TV-Gaming (Mehrspieler)

    
Bei jedem Mehrspieler-Spiel (📱 Handy-Controller, 🌐 Online, 👥 Mehrspieler) zeigt easygames den richtigen Link für den TV: die öffentliche Spielseite, bei Spielen mit TV-Parameter inklusive ?tv. Der TV-Browser öffnet sie direkt als Vollbildseite, die Handys koppeln sich dann per QR-Code im Spiel.

    
Wo der TV-Link erscheint

    
    
      
  • Übersicht: im Anleitungsfenster (📖) und im Teilen-Dialog jedes Mehrspieler-Spiels, mit Kopieren-Knopf.
    • 
      
  • Eingebundene Spiele auf anderen Seiten: easygames.js setzt unter jedes Mehrspieler-Spiel die Zeile „📺 Am TV spielen: …“ mit Link und Kopieren-Knopf. Ausblenden mit data-tv-link="false" bzw. tvLink: false.
    • 
      
  • Eigene Oberfläche: EasyGames.tvUrl('anmacha-kart') liefert den Link (für Einzelspiele null). EasyGames.list() enthält multiplayer, modes und tvUrl.
    • 
      
  • Im Spiel selbst: EasyGamesKit.tvUrl() – zum Anzeigen oder als QR-Code für den TV.
    • 
    

    
Auch in Apps und auf anderen Seiten richtig

    
Ein TV oder ein anderes Handy kann keine Adresse einer App, von localhost oder aus dem lokalen Netz öffnen. Deshalb gilt die feste Mehrspieler-Regel: TV-, Einladungs- und Spiellinks zeigen immer auf die easygames-Homepage, damit sie plattformübergreifend funktionieren:

    
    
      
  1. Ist window.EASYGAMES_PUBLIC_BASE gesetzt, gilt diese (z. B. deine eigene Domain).
    2. 
      
  2. Sonst immer die Homepage https://ricorewioriginal-collab.github.io/easygames/ – auch in der App, unter file://, localhost oder im lokalen Netz.
    3. 
    


<script>
  // vor easygames.js bzw. device.js setzen – nur nötig, wenn die Spiele auf einer eigenen Domain liegen
  window.EASYGAMES_PUBLIC_BASE = 'https://spiele.meine-seite.de/';
</script>

    
Der TV braucht Internet, auch wenn die Spiele in der App offline laufen: Er öffnet die öffentliche Seite. Läuft das Spiel selbst bereits auf dem TV, wird kein TV-Link gebraucht.

    
Neues Mehrspieler-Spiel

    
Sobald ein Spiel in modes.js (oder am Eintrag in games.js) pad, online oder multi hat, erscheint der TV-Link überall automatisch. Hat das Spiel einen Parameter, der am TV direkt die Lobby öffnet, kommt tvParam dazu.

  


  

    
Neues Spiel hinzufügen

    
Neue Spiele erscheinen automatisch in Übersicht, Suche, Generator, Einbettung und TV-Navigation. Dafür sind nur wenige Einträge nötig:

    

      
SchrittDateiInhalt

      
1mein-spiel/index.htmlDas Spiel. Vorlage: tools/spiel-vorlage/index.html

      
2games.jsid, title, icon oder img, bg, glow, path, desc

      
3modes.js oder modes:{…} am Eintragpad (Handy-Controller), online, multi, tvParam

      
4guides.jsanleitung, steuerung, tipps

      
5python3 tools/make-pwa.pyMacht das Spiel als App installierbar (PWA)

      
6gamepad.js (optional)Gamecontroller-Unterstützung, wenn das Spiel keine eigene hat (Gamecontroller)

      
7anmacha-cloud.js (optional)Cloud-Speicherstand per Google (Cloud-Speicher)

      
8node tools/check-games.jsPrüft IDs, Pfade, Bilder, Anleitungen, Modi

    

    
Was passiert ohne Eintrag?

    
    
      
  • Ohne modes: Das Spiel ist ein normales Einzelspiel, ohne Abzeichen und Filter.
    • 
      
  • Ohne guides.js-Eintrag: Das Anleitungsfenster zeigt die Kurzbeschreibung.
    • 
      
  • Ohne img: Auf der Karte erscheint das Icon mit dem Farbverlauf.
    • 
      
  • Filterknöpfe (📱 / 🌐 / 👥) erscheinen nur, wenn mindestens ein Spiel die Art hat.
    • 
    

    
Spiel-Vertrag

    
    
      
  • Das Spiel füllt die ganze Seite (100vw × 100dvh, kein Scrollen) und läuft auch in einem iframe.
    • 
      
  • Es ist mit Touch, Tastatur und am TV mit Pfeiltasten und OK bedienbar, und mit einem Gamecontroller (eigene Steuerung oder gamepad.js).
    • 
      
  • Handy als Controller: Das Spiel läuft am PC/TV als Gastgeber und zeigt einen QR-Code mit …/mein-spiel/?join=CODE. Öffnet jemand die Seite mit ?join=, wird das Gerät zum Controller.
    • 
      
  • TV: Optional ein Parameter (üblich: ?tv), der direkt die Lobby mit QR-Code zeigt. Dann in modes.js tvParam: true setzen.
    • 
      
  • Eigene Zurück-Taste (z. B. Pause-Menü)? Mit EasyGamesKit.back(fn) übernehmen, sonst schließt die Übersicht das Spiel.
    • 
    

    
gamekit.js – fertige Bausteine


<script src="../device.js"></script>
<script src="../gamekit.js"></script>

  EasyGamesKit.start({

7. postMessage – Spiele sprechen mit der Übersicht

    
Läuft ein Spiel im Viewer der Übersicht, kann es Nachrichten senden:


parent.postMessage({ type: 'easygames:close' }, '*');   // Spiel schließen
parent.postMessage({ type: 'easygames:menu'  }, '*');   // Menüleiste zeigen
parent.postMessage({ type: 'easygames:next'  }, '*');   // nächstes Spiel
parent.postMessage({ type: 'easygames:prev'  }, '*');   // voriges Spiel

    
Nur Nachrichten aus dem Spiel-Frame der Übersicht werden beachtet. Mit easygames.js (Overlay) gilt easygames:close ebenfalls.

    
Zurück zur Spieleansicht der Seite

    
Ein Spiel in einem Overlay oder iframe kann mit „← Alle Spiele“ (href="../") zurückgehen – das funktioniert ohne Zutun: Öffnet sich die easygames-Übersicht in einem Rahmen (ohne ?embed=1), meldet sie easygames:close an deine Seite. Ein Overlay schließt dadurch, ein fest eingebetteter Rahmen zeigt stattdessen die eingebettete Spieleliste. Ein eigener Zurück-Knopf im Spiel kann direkt EasyGamesKit.close() (gamekit.js) bzw. parent.postMessage({ type: 'easygames:close' }, '*') senden.

  


  

    
8. In einer App (auch offline)

    
Was in die App muss

    
    
      
  • Die Spielordner (je Spiel ein Ordner mit allen Dateien) – für Direktlinks reicht das.
    • 
      
  • Für die Übersicht zusätzlich: index.html, device.js, gamekit.js (für neue Spiele), games.js, modes.js, guides.js und optional easygames.js. Fehlen games.js und guides.js, bleibt die Übersicht leer.
    • 
      
  • Für Ranglisten und Erfolge zusätzlich: ranglisten.html, erfolge.html, cloud/anmacha-cloud.js, cloud/anmacha-board.js, cloud/anmacha-ach.js, cloud/anmacha-gameach.js und sync/catalog.json (siehe 5b).
    • 
      
  • Alle Pfade sind relativ. Die Ordnerstruktur darf nicht verändert werden.
    • 
      
  • Die Dateien laden nichts aus dem Internet. Einzelne Spiele können dennoch Online-Funktionen haben (z. B. Mehrspieler per Code/QR, Speicherstand per Google).
    • 
    

    
Empfehlung

    
Öffne in der App entweder die Übersicht (index.html) oder ein Spiel direkt in einer Vollbild-WebView – nicht als iframe in einer anderen Seite. Das vermeidet Probleme mit Vollbild und Zurück-Taste.

    
Dateien laden: file:// oder https?

    
    
      
  • file:// funktioniert für einfache Spiele. Aber: Der Browser sieht jede Datei als eigene Herkunft. Die Übersicht kann dann nicht in das Spiel hineinhören (Zurück-Taste im Spiel wird nicht abgefangen), und manche Spiele mit Modulen, Wasm oder Speicherung brauchen einen richtigen Ursprung.
    • 
      
  • Besser: ein lokaler https-Ursprung – bei Capacitor/Cordova ist das https://localhost bzw. ein App-Schema, bei Android WebViewAssetLoader, bei iOS ein WKURLSchemeHandler.
    • 
    

    
Beispiel Android (Kotlin)


val web = findViewById<WebView>(R.id.web)
web.settings.javaScriptEnabled = true
web.settings.domStorageEnabled = true
web.settings.mediaPlaybackRequiresUserGesture = false
// Assets unter https://appassets.androidplatform.net/assets/ ausliefern:
val loader = WebViewAssetLoader.Builder()
    .addPathHandler("/assets/", WebViewAssetLoader.AssetsPathHandler(this)).build()
web.webViewClient = object : WebViewClientCompat() {
    override fun shouldInterceptRequest(v: WebView, r: WebResourceRequest) = loader.shouldInterceptRequest(r.url)
}
// Vollbild aus HTML5 (onShowCustomView/onHideCustomView) im WebChromeClient umsetzen
web.loadUrl("https://appassets.androidplatform.net/assets/easygames/index.html")
// Zurück-Taste: if (web.canGoBack()) web.goBack() else finish()

    
Beispiel iOS (Swift)


let cfg = WKWebViewConfiguration()
cfg.allowsInlineMediaPlayback = true
cfg.mediaTypesRequiringUserActionForPlayback = []
let web = WKWebView(frame: .zero, configuration: cfg)
let dir = Bundle.main.url(forResource: "easygames", withExtension: nil)!
web.loadFileURL(dir.appendingPathComponent("index.html"), allowingReadAccessTo: dir)
// Zurück: web.allowsBackForwardNavigationGestures = true

    
Die Beispiele sind Ausgangspunkte. Bitte in deiner App mit echten Geräten prüfen: Vollbild, Ton, Zurück-Taste und Speicherstand verhalten sich je nach Version unterschiedlich.

    
Ton und Touch

    
    
      
  • Ton startet erst nach einer Berührung. Deshalb mediaPlaybackRequiresUserGesture = false (Android) bzw. mediaTypesRequiringUserActionForPlayback = [] (iOS) setzen.
    • 
      
  • Hardware-Zurück der App an die WebView weitergeben, damit die Übersicht ein Spiel schließen kann.
    • 
    

  


  

    
9. Eigener Server und Pfade

    
    
      
  • Die Ordner können auf jeden statischen Webspace kopiert werden. Alles läuft rein im Browser, ein Server wird nicht benötigt (Ausnahme: Online-Mehrspieler bei einzelnen Spielen).
    • 
      
  • In games.js ist path ein Ordner relativ zur Übersicht oder eine komplette URL. So lassen sich Spiele auch von woanders einbinden.
    • 
      
  • Neues Spiel? Einen Eintrag in games.js ergänzen und optional eine Anleitung in guides.js.
    • 
      
  • Schickt dein Server X-Frame-Options: DENY oder ein restriktives frame-ancestors, lassen sich die Seiten nicht in iframes einbetten. GitHub Pages erlaubt das.
    • 
      
  • Auf https-Seiten dürfen nur https-Spiele eingebettet werden (sonst blockiert der Browser gemischte Inhalte).
    •
